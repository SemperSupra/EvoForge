# Adaptive workspace accessibility lab

This standalone, dependency-free browser example demonstrates stable panels, linked synthetic candidate selection, collapse/hide/restore, focus, DOM-order changes, widening, system/light/dark appearance, adjustable relative text size, and persistent presentation preferences. The fixture has no evolutionary or deployment authority. It is not part of the served application.

Open via a local static HTTP server from this directory, or run the automated checks from the repository root on a disposable environment with the locked Playwright dependency and appropriate installed browser: `node examples/adaptive-workspace/qualify.mjs chromium` (also firefox/webkit). Standard public GHA runs the four platform cells. Receipts and screenshots are artifacts. The checks use actual keyboard and pointer operations, appearance changes, reflow and focus recovery. They do not establish WCAG conformance or screen-reader compatibility. Manual NVDA, VoiceOver, TalkBack, keyboard-only and low-vision evaluation remains required. No third-party fonts or external services.

Guidance: [WCAG 2.2](https://www.w3.org/TR/WCAG22/), [ARIA disclosure](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/), [Apple split views](https://developer.apple.com/design/human-interface-guidelines/split-views), [Android canonical layouts](https://developer.android.com/develop/adaptive-apps/guides/canonical-layouts), [Microsoft inclusive software](https://learn.microsoft.com/en-us/windows/apps/design/accessibility/designing-inclusive-software). Default controls follow native web conventions; reorder changes DOM reading order. The shared shell is an experimental component, not a replacement for the production UI.
