# Alpine execution profiles (experimental)
Purpose-specific images, not a deployment of the PWA. GitHub Pages needs no runtime image.
The Dockerfile separates base, Node runtime, compiler and optional debug capabilities. The APK-native compiler is an independent comparison against the exact Node/npm donor binaries from the previously evaluated image. No browser dependencies in any compiler. Browser qualification uses separate supported runners. A Node runtime is a reusable service profile, not needed for the PWA itself.
Build with `docker build --target compiler --build-arg ALPINE_BASE=alpine@sha256:... --build-arg NODE_DONOR=node@sha256:... -f containers/alpine/Dockerfile containers/alpine`.
The trial resolves the public Alpine tag to an immutable digest, keeps the donor pinned, captures the resolved APK inventory, package details, image identity, filesystem manifest, version and binary checksums, SBOM and vulnerability reports. APK repositories remain time-varying: exact package archive/lock and repeat image build are required before claiming reproducible image construction. Copied Node/npm files are not APK-managed: track donor identity, licenses and binary/npm inventory separately; OS-only scanner coverage is not complete security assurance.
No privileged containers, no private credentials, no automatic deployment. Default UID/GID 10001, runtime has no npm or debug tools. Build trial uses host runner UID for disposable writable source, drops capabilities, uses no-new-privileges. No arbitrary package removal from an approved image: change explicit declarations, requalify, retain evidence. SUSE remains compatibility fallback, not an active minimization target.
